# План развития CoC Clan Bot

Обновлено: 25 октября 2026 года. Привязки участников временно отложены.

## 1. Доступ по привязке участника — отложено

Привязки участников и команды `/link_member` и `/unlink_member` пока убраны из бота. Сейчас команды клана доступны в назначенной группе, а в личных сообщениях работают только `/start` и `/help`. Пункты ниже относятся к возможному возвращению функционала привязок.

- [ ] Разрешать функции бота только пользователям, которых привязал администратор.
- [ ] Вернуть команды `/link_member` и `/unlink_member` для управления привязками.
- [ ] Проверять допуск для команд и нажатий кнопок; сохранить управление ботом для администратора.
- [ ] Учесть несколько игровых аккаунтов на один Telegram ID: предоставить доступ ко всем своим привязанным аккаунтам; удаление последней привязки отзывает доступ.
- [ ] Сохранять привязки и доступ при выходе из игрового клана, включая временные выходы. Для допуска проверять наличие привязки; отзывать её вручную через `/unlink_member`.
- [ ] Определить список команд, доступных посторонним.

## 2. Клавиатуры для команд

- [ ] Выбрать команды, которым нужны кнопки.
- [ ] Добавить клавиатуры и обработку нажатий в самом боте.
- [ ] Проверять права пользователя и обрабатывать повторные и устаревшие нажатия.

## 3. Адресные напоминания об атаках на КВ

Общие уведомления о КВ уже есть; нужно добавить пинги конкретных участников.

- [ ] За 2 часа до конца КВ проверять, забраны ли все возможные звёзды. Если да — не напоминать.
- [ ] Иначе находить участников с оставшимися атаками и пинговать тех, у кого есть Telegram-привязка.
- [ ] Объединять аккаунты одного человека в одном напоминании; исключить повторную рассылку, в том числе после перезапуска.
- [ ] Выбрать место отправки: тема КВ или личные сообщения. Определить поведение, если бот пропустил двухчасовой порог.

## 4. Сбор состава на КВ

- [ ] Дать участнику возможность согласиться на КВ или отказаться, выбрав свой привязанный игровой аккаунт.
- [ ] Сохранять ответы для конкретного набора и разрешать менять решение до закрытия записи.
- [ ] Показывать ответы и формировать состав из согласившихся без повторного включения одного аккаунта.
- [ ] Определить открытие и закрытие записи, размер состава, правила отбора и необходимость подтверждения администратором.

## Отложено

Оптимизация обращений к БД и in-memory кеширование — вернуться при конкретной необходимости. Сейчас отдельные замеры и внедрение кеша в план работ не входят.
